# 钢了钢

Vue 3 / Vite 叠叠三消游戏，包含 Capacitor Android App、单人闯关、情侣同玩及独立开发者后台。

- **单人模式**：选牌和三消本地即时响应，不发送点击、卡牌选择或心跳日志。后台只处理关卡、库存与奖励等有意义操作，断网仍可选牌；首次离线为本地练习。
- **情侣模式**：四位密码加入两人房间，共用棋盘、卡槽、暂存区、消除动画与弹窗；双方各自消耗个人道具；WebSocket 双向同步，刷新及断线自动恢复。
- **共用背包**：道具和心愿券归个人所有，跨关卡、跨游戏保留。新身份只获得一次透视卡 2 张、召唤男友卡 1 张，开局和重开不再补满；救场最多暂存三张牌。
- **概率奖励**：道具与心愿券可配置 0–100% 概率；共同获取可独立抽取多种，关闭时最多一种且允许空奖。情侣双方分别领奖，关键资产与回执由后台事务记账。旧版无所有者券明确保留为共享券。
- **有意义记录**：IP、设备、App/网页/开发者来源、关卡与耗时、道具及券的获得和使用；后台支持过滤、分页和可选自动刷新。
- **独立后台**：浏览器 /admin 或 /gang/admin，开发者管理规则、卡牌、照片、券池、房间、库存和日志。保存后停留后台，游戏与 App 内没有后台入口。

## 本地开发

运行 npm ci 安装依赖，npm start 启动 API；另开终端运行 npm run dev。API 默认端口 3000，Vite 转发 /api 和 /photos。首次后台密码为 admin，可在“密码安全”中修改。本地默认 JSON 开发适配器；生产使用已有 PostgreSQL 17 独立库、专用账号和最多 5 个连接，接入与迁移前备份见 [POSTGRES_SETUP.md](POSTGRES_SETUP.md)。配置和上传照片仍存放在 data/，应一并备份。

## 关卡和照片

关卡数量和每关卡片数量没有固定上限，卡片数量至少 6 张，支持 1–12 种牌型和 1–8 层基础叠层；后台可配置棋盘与卡片尺寸、初始/最大卡槽、逐格解锁条件、布局范围、形状和扰动。超出基础叠层容量时自动增加叠层，520、1314 等整数按原值保存；严格按同类三张消除；固定张数不是 3 的倍数时显示明确提示和建议值，保留所填写的数量，不自动消除零头。几何和牌库变更下局应用。

卡片数量符合三消要求时，保底与高压模式按初始卡槽容量构造可通关路径；高压模式优先占满不同牌型的未完成组合，让卡槽反复接近满槽，默认第 2 关起采用高压模式；普通模式随机分配整组三张牌，不承诺无道具可解；绝对死局模式在至少两种牌型时制造无法三消的孤儿牌。生成器和游戏规则由前端与服务器共享。

9 种造型按结构复杂度排列，支持菱形、爱心、十字、环形、蝴蝶、金字塔、沙漏和城堡。“男友帅照”迁移为普通默认分组，卡片可重命名、换图和移动分组；每关可多选使用分组，默认全选。救场形象独立设置。

后台“卡牌种类与图片 → 卡片文字”支持仅图片、名称、名称与描述，提供实时预览；统一控制棋盘、卡槽与暂存区，情侣双方同步生效，无需重开。图片本身包含的文字不受此设置影响。旧配置默认显示名称。卡片和券池可直接编辑名称、描述，修改自动保存；关卡表单可单独保存，也可使用“保存全部配置”。

## 代码结构

- `shared/`：前后端共用的默认配置、参数规范化、布局、关卡生成和游戏规则；`gameplayServer.js` 负责房间与原子账本。
- `src/utils/useGame.ts`：游戏交互、单人本地状态与情侣同步；`src/components/`：卡片、模式、卡槽、道具及共用弹窗。
- `src/AdminApp.vue`：独立后台入口，按卡片、照片、券池、关卡、运行账本、日志和安全设置拆分组件；Android 构建不包含后台。
- `server.js`：API、开发者认证和存储入口；`tests/` 与 `scripts/verify-*-production.mjs`：交互回归和实际构建验证。

## Android

版本 **2.0.0 / versionCode 5**，包名 com.love.ganglegang。后台由 .env.android 固定，无需玩家配置。Java 21 和 Android SDK 36 准备好后运行：

    powershell -ExecutionPolicy Bypass -File scripts/build-android.ps1 -JdkPath 'JDK目录' -SdkPath 'Android SDK目录'

输出 artifacts/android/ganglegang-2.0.0.apk 与 SHA256，沿用当前 Windows 用户 .android/ganglegang-signing 密钥。仅同步工程使用 npm run build:android。规则、数据保留、同步与故障边界见 [ANDROID_ONLINE.md](ANDROID_ONLINE.md)。

## 验证

npm test 执行 Playwright 测试，npm run build 进行类型与生产构建检查。测试覆盖随机关卡、极端尺寸、多种屏幕宽度、实际点击通关、单人本地操作、双向房间同步、去重与并发交易、后台保存冲突、存储损坏保护及部署失败回滚。默认浏览器为本机 Edge，可通过 PLAYWRIGHT_CHANNEL=chrome 调整。

npm run test:inventory 另外验证 432 个布局牌局和真实 PostgreSQL 17 的备份迁移、回滚、身份隔离、重启与去重。Windows 测试首次下载官方 pg_dump 客户端并缓存到 node_modules；也可用 PG_DUMP_BIN 指定已有客户端。

房间由单 Node 进程处理，数据库会话锁阻止重复实例。关键资产等待事务提交后才确认，普通情侣牌面每秒合并保存，硬故障时最近约一秒普通进度可能回退。单人模式不上传完整操作证据，因此暂无服务端逐步通关校验。多实例、账号绑定、主页与角色换装的扩展接口和分期设计见 [PLATFORM_DESIGN.md](PLATFORM_DESIGN.md)。构建脚本不会自动发布或部署。

默认男友心愿、女友心愿各 12 项，均可选择吃饭、饮料、按摩、家务、电影等，描述写明由另一方兑现或买单。已有自定义心愿可保留，后台提供补充默认心愿入口。

App 记录打开、切到后台、回到前台和明确退出，包含本次打开编号、前台使用与后台停留时间；断网时在本机暂存，联网或下次打开时补报，服务器跨重启去重。后台日志可按类型、事件、来源、日期、设备和本次打开筛选，支持 IP、型号和心愿名称搜索，显示中文摘要与设备信息。系统强制结束进程可能不产生退出通知。

本轮只修改源码和默认配置，未更新 APK 或打包。原生 App 生命周期使用 @capacitor/app，后续正式构建时同步该插件；当前已安装 APK 不会自动获得这些源码改动。
